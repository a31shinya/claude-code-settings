## Environment
- OS: macOS Sequoia
- Runtime: Python3.13 / pip
- Framework: AWS SAM(Image)
- DB: DynamoDB
- デプロイ先: AWS Lambda

## Work Rules & Principles
以下の原則を最優先して作業を実行すること。

### 1. コーディング前に考える (Think Before Coding)
- わからないことは「わからない」と明確に伝え、推測で作業を進めないこと。
- 複数の解釈が存在する場合は、勝手に1つを選ばず、選択肢やトレードオフを提示して確認を求めること。
- よりシンプルなアプローチがある場合は提案（Push back）し、混乱した場合は作業を止めて明確化を求めること。

### 2. シンプルさ最優先 (Simplicity First)
- 問題を解決する最小限のコードを書くこと。要求されていない機能追加や、推測に基づく拡張はしないこと。
- 単一用途のコードに対する抽象化や、要求されていない「設定の柔軟性」は実装しないこと。
- 50行で済む処理を200行で書くような、過剰に複雑な実装（オーバーエンジニアリング）を避けること。

### 3. 局所的な変更 (Surgical Changes)
- 必要な部分のみを変更し、既存のコードスタイルに合わせること。
- 壊れていない箇所の勝手なリファクタリングや、タスクに無関係なコード・コメントの「改善」は行わないこと。
- 自身の変更によって不要になった変数やインポートは削除するが、既存の不要コード（デッドコード）は指示されない限り削除しないこと。

### 4. 目標主導の実行 (Goal-Driven Execution)
- 曖昧な指示は、検証可能な「成功基準」に変換してから実行すること（例：「バグを修正する」ではなく、「バグを再現するテストを書き、それを通過させる」など）。
- 複数ステップのタスクでは事前に短い計画を提示し、条件が満たされるまで自律的に検証ループを回すこと。

### 5. 成果物とバージョン管理のルール
- 成果物はチャットにテキストを流すだけでなく、必ずファイルに保存・適用すること。
- 1つの論理的な変更につき1コミットとすること。複数の変更をまとめてコミットしないこと。
  
## Commands
- パッケージ追加: `pip install <package>` 実行後、必ず `requirements.txt` を更新し、`sam build` 時にパッケージ内容が失われないようにすること。
- テスト実行: `pytest`
- ビルド: `sam build`
- デプロイ: `sam deploy`

## Project Conventions
- **AWS Lambda & SAM (Image):** コンテナイメージベースのデプロイであるため、依存関係を追加した際は `requirements.txt` の更新と合わせて、必要に応じて `Dockerfile` の確認も行うこと。
- **DynamoDB:** データの読み書きには `boto3` を使用し、非効率な `scan` 処理は避け、パーティションキー（およびソートキー）を用いた `query` を心がけること。
- **IAM権限:** LambdaからDynamoDB等へアクセスする際は、必ずAWS SAMのテンプレート（`template.yaml`）に最小権限のポリシーを追加すること。

## Compaction Rules
会話履歴を要約（compact）する際は、以下の情報を必ず残すこと：
- 現在取り組んでいるバグの仮説と、これまでに変更したファイル一覧
- 解決していないテストの失敗メッセージや、ビルド・デプロイ時のエラーログ
- 未完了のTODOリスト
