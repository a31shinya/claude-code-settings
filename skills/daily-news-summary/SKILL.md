# Daily News Summary

NotebookLMに日次で投入された日経ニュースを、固定フォーマットの解説レポートに整形するスキル。

## 使う場面

- 「今日のニュースまとめて」「2026年5月4日の日経まとめて」のような依頼
- 「ニュースを深掘りして解説して」のような依頼
- ユーザーが日付を指定したらその日付、指定なしなら**本日（システム上の今日の日付）**を対象にする

## 前提

- ニュース記事は NotebookLM の **`[nikkei-news]YYYY/MM/DD`** という名前のNotebookに格納されている
- NotebookLM へのアクセスは **MCP（`mcp__notebooklm-mcp__*` 系ツール）** 経由で行う
- 出力は **Markdown 1ファイル**を、現在の作業ディレクトリ（`pwd`）配下の `summary/` フォルダに保存する
- 言語は **日本語固定**

## 全体フロー

1. 対象日付を確定する
2. NotebookLM から該当Notebookを特定する
3. その日の主要5軸を抽出する
4. 5軸それぞれを深掘りクエリで肉付けする
5. テンプレートに整形して `summary/news-YYYY-MM-DD-主要トピック.md` に保存する

各ステップの詳細は以下。

---

## Step 1: 対象日付の確定

- ユーザーが日付を指定していれば（「5月4日の」「2026/05/04の」など）その日付を採用
- 指定がなければ **本日の日付** を `date +%Y-%m-%d` などで取得して採用
- 以降のフォーマット用に2形式を保持しておく：
  - `YYYY-MM-DD`（ファイル名・本文用、例: `2026-05-04`）
  - `YYYY/MM/DD`（Notebook検索・出典表記用、例: `2026/05/04`）

## Step 2: Notebookの特定

`mcp__notebooklm-mcp__notebook_list` で全Notebookを取得し、タイトルが `[nikkei-news]YYYY/MM/DD` と完全一致するものを探す。

- 見つかったらそのNotebook IDを保持
- 見つからなかった場合はユーザーに「指定日のNotebookが見つかりません」と伝えて停止（勝手に近い日付で代用しない）

## Step 3: 主要5軸の抽出

NotebookLMに対して**1回のクエリ**で5軸を抽出する。テーマ／カテゴリ単位の軸（例: 米中関係、半導体、金利・為替、AI規制、エネルギー など）を返してもらう。

クエリ例（このまま使ってよい。必要に応じて微調整）：

```
このNotebookに含まれるニュース全体を俯瞰し、本日の主要なテーマ／カテゴリを5つに分類してください。
各軸について以下を JSON ライクな構造で返してください。

- axis_name: テーマ名（例: 米中関係、半導体、金利・為替 など。10字以内が望ましい）
- one_line_summary: その軸を一行で表す要約（60字以内）
- related_articles: その軸に該当する記事タイトルの配列

出力例:
1. 軸名: ○○
   一行要約: ...
   関連記事:
     - 記事タイトルA
     - 記事タイトルB
2. 軸名: ...
（5つまで）

軸は重複なく、Notebookの記事を可能な限り網羅できるよう選んでください。
```

`mcp__notebooklm-mcp__notebook_query`（同期）で送る。**結果がファイル書き出し時点までに揃っていればよい**ので、軸抽出は同期で問題ない。

返答が崩れていたり5軸揃っていない場合は、もう1回だけ追加で問い合わせる。それでもダメなら、揃った分だけで進めて足りない箇所には `★★★回答不明★★★` を入れる。

## Step 4: 各軸の深掘り

5軸それぞれについて、次の **5要素** を埋めるクエリをNotebookLMに投げる：

1. **背景** — 歴史的・構造的な前提（200〜400字目安）
2. **発生した事象** — 事実ベース（200〜600字目安、短い箇条書きが向く場合は箇条書き）
3. **何が問題なのか** — 影響範囲・ステークホルダー・論点（200〜600字目安、箇条書き可）
4. **良いところは何なのか** — プラスの影響・機会・受益者（200〜600字目安、箇条書き可）
5. **今後の展望** — 短期・中期の予想、注視すべき指標やイベント（200〜600字目安）

### 効率的なクエリの投げ方

軸ごとに **1クエリで5要素まとめて取得**するのが効率的。クエリ例：

```
テーマ「{{軸名}}」について、Notebook内の関連記事を踏まえて以下の5観点で解説してください。
それぞれ見出しを付けて区切ってください。

## 背景
（200〜400字。歴史的・構造的な前提）

## 発生した事象
（200〜600字。事実ベース。箇条書きが適切なら箇条書きで）

## 何が問題なのか
（200〜600字。影響範囲、ステークホルダー、論点。箇条書きが適切なら箇条書きで）

## 良いところは何なのか
（200〜600字。プラスの影響、機会、受益者。箇条書きが適切なら箇条書きで）

## 今後の展望
（200〜600字。短期・中期の予想、注視すべき指標やイベント）

冗長な前置きや「以下に解説します」のような枕詞は不要。本文だけ書いてください。
```

### 5軸を並行で投げる

軸ごとのクエリは独立しているので、**5軸まとめて並行に投げて待つ**のが速い。`notebook_query_start` で5本同時にキックして `notebook_query_status` でポーリング、または同期 `notebook_query` を順に呼ぶでも可（仕様上どちらでもよいが、並行のほうが速い）。

**重要**: ファイル書き出し時点までに**全軸×5要素が揃っていること**。途中で書き出してはいけない。

### 不調時のリトライ

ある軸の回答が空・要素欠落・明らかに記事と無関係 などで「不調」と判断したら、**3回まで**追加クエリで再取得を試みる。リトライは10秒程度時間を置いてからリトライする。それでもダメなら該当箇所に `★★★回答不明★★★` を入れる。

リトライ判定の目安：
- 回答が100字未満（短すぎ）
- 5要素のうち2つ以上の見出しが欠落
- エラーメッセージや「分かりません」系の応答

## Step 5: 整形と保存

### テンプレート

`assets/template.md` を読み込み、placeholder を実データで置換する。テンプレートの章立ては以下で固定：

```
# 日経ニュースまとめ YYYY-MM-DD

## サマリー
- **軸1（軸名）**: ひとこと要約
（5軸）

---

## 1. 軸名

### 関連ニュース
- 記事タイトル列挙

### 背景
### 発生した事象
### 何が問題なのか
### 逆に良いところは何なのか
### 今後の展望

---

（軸5まで同じ）

---

## 出典
- Notebook名: [nikkei-news]YYYY/MM/DD
- 生成日時: YYYY-MM-DD HH:MM
```

### 保存先

```
{pwd}/summary/news-YYYY-MM-DD-主要トピック.md
```

- `主要トピック` は**固定の日本語文字列**（軸名を入れるのではない、リテラル）
- `summary/` ディレクトリが無ければ作成する（`mkdir -p`）
- 同名ファイルが既にあれば**上書き**してよい（同じ日のレポートは1つに統一）

### 整形ルール

- 章立て・見出しレベルは**テンプレートのまま厳守**（他の日と章立てを揃えるため）
- 各軸の本文中に NotebookLM の応答が独自の見出し（## など）を勝手に出していたら、テンプレートの `###` 階層に揃えるよう書き換える
- 「以下に解説します」「ご質問の件について」のような前置きは削除
- 不明箇所は `★★★回答不明★★★` で明示

## 完了報告

ファイルを書き出したら、ユーザーに保存先の絶対パスと、抽出した5軸の名前を報告する。

例：
```
保存しました: /Users/.../summary/news-2026-05-04-主要トピック.md
抽出した5軸: 米中関係 / 半導体 / 金利・為替 / AI規制 / エネルギー
```

---

## NotebookLM MCPの認証エラー対処

`mcp__notebooklm-mcp__*` 系ツールが認証エラーを返した場合は、ユーザーにターミナルで `nlm login` を実行するよう促す（自分で実行はできないので、`! nlm login` をプロンプトに打つよう案内する）。

## やってはいけないこと

- 別の日のNotebookで代用する（指定日が無ければ停止して報告）
- 5軸揃わないまま全部 `★★★回答不明★★★` で埋めて完成扱いにする（最低限、軸抽出は通ってから進める）
- ファイル名の `主要トピック` を勝手に軸名に置き換える（リテラル固定）
- 章立てを勝手にカスタマイズする（他の日と揃えることが最優先）
